### 2. Reframe v1 as 'Assistant DSI: a substitution product' and defer the entire T5/cloud tier to a gated v2, proven first by a short consent-based pilot
_facet: whole-system-coherence-and-what-to-cut_

**Why:** The deliverable is a behaviour change — agents stop pasting citizen/agent data into public ChatGPT because a sanctioned tool exists — not an AI capability, and nothing in the adopted set de-risks that central bet: that agents will accept a slower (~3 tok/s), narrower tool. A stratified... in practice volunteer pilot answers that in ~2–3 weeks of work instead of a permanent 2–3 person commitment to ~24 subsystems. Deferring T5 deletes the single largest coherent cost cluster: cloud_authorization.yaml runtime, SCC+TIA shipping regime, LiteLLM logging-off plumbing, workspace-scoped key + server-side hard cap, durable t5_ledger, Article 9 lexicon gate, GLiNER anonymisation tuned for cloud + outbound re-scan, T5 fail-closed tests — because every T5 call is legally an Article 46 transfer, so if the shadow-egress KPI moves WITHOUT cloud, that surface never needs to exist. The Article 46 / SCC / TIA / DPA legal groundwork still starts in parallel now (months-long lead time, on the critical path for any future cloud tier and owned by the dossier at rank 1), but the runtime machinery waits for a v2 gate with pre-committed go/no-go criteria. Pair with the two-gate legal split: pilot_authorization.yaml on Art. 6(1)(a) consent for a genuinely voluntary, no-detriment, pseudonymous, delete-by-default cohort unblocks the eval-harness corpus and canonical-base seeding that cannot be produced from a paper description.

**Sketch:** Write a v1 scope doc: ships = curated canonical answer base + strong French search + one constrained 'rediger / reformuler un courriel' lane on local T2/T3 + the DNS shadow-egress KPI measured against a real baseline of current ChatGPT use. No T5 runtime. pilot_authorization.yaml gate: ~15–25 DSI + immediately-adjacent volunteers, hard end date in the gate matching a 6–8 week window, pseudonymous logging, delete-by-default at pilot end with NO re-consent path (Stage B starts clean on 6(1)(e)). All safeguarding / PII pre-screen / no-clear-text-to-cloud controls live BEFORE the pilot opens. Mixed-method KPI: DNS/proxy signal directional only + structured before/after diary + exit interviews + a count of 'fall-through' queries the tool refused or answered badly. Pre-commit written go/no-go thresholds and a hard v2 decision date so the pilot cannot enter permanent limbo. Manage stakeholder expectations explicitly: v1 is a substitution product, not a ChatGPT replica. Keep cloud_authorization.yaml and the dossier's Article 46 track alive but unbuilt. Work: ~2–3 weeks to stand the pilot up; saves an estimated 6–9 months of build if the bet fails or if the KPI moves without cloud.

### 3. Collapse observability + DR + data-subject-rights ops into one weekly 'revue d'exploitation' + git-as-source-of-truth, with a minimal 4-signal real-time alert path
_facet: whole-system-coherence-and-what-to-cut_

**Why:** This converts 'always-on watches nobody performs' (Prometheus/Grafana are already unwatched, so removing them loses zero real value) into a bounded ~10-minute weekly task a 2–3 person team can actually sustain, and it makes the recurring human cost legible so DPO/DGRH/DAF time can be budgeted honestly. Git-as-truth makes the disaster case a redeploy of compose from git, not a rehearsed failover — the right posture for a best-effort internal assistant. The proposal concedes its own hole and that concession is the design: leak-canary fire, PII-screen fail-open rate, safeguarding-counter spike and disk-full cannot wait 7 days, so a minimal push alert path for ~4 signals still has to exist — and it shares a channel and rota with the security tripwires at rank 5, so it is not a second alerting system. The 'identity-linked query log' the digest reads from is a RGPD honeypot on a box with unauthenticated ports: it needs its own DPIA paragraph and a hard 30–90 day retention with restricted access, or — especially in a no-T5 v1 where per-agent patterns matter less — drop identity-linking and keep aggregate per-verb counts. A weekly ritual on a tiny team decays across holidays without a named owner and a skip-escalation rule.

**Sketch:** One weekly digest cron emailing: shadow-egress KPI, volume per verb, signaler queue depth, error rate, disk free, plus 'derniere sauvegarde verifiee' and 'dernier test de restauration' fields. Named ritual owner + backup + an 'if skipped 2 weeks, escalate to the chef de cellule' rule. A minimal real-time push path (email/SMS) for exactly 4 alerts — canary fire, PII fail-open rate, safeguarding spike, disk-full — reusing the security-tripwire channel. Give the identity-linked query log an explicit short retention job, restricted access, and its own data_manifest.yaml / DPIA section, or replace it with aggregate per-verb counters. DR = redeploy from git + restore last nightly corbeille dump; the digest's restore-test field forces the dump to actually be verified. Written sign-off on the 24h corbeille RPO and a documented proportionality rationale for annual (not monthly) erasure testing for CNIL. Defer the second-island DR box, quarterly game-day and arrival-rate tooling to v2 (see open questions). Work: ~1 week.

### 4. Structural log minimisation: emit_event() + Agent Anone as a verdict-only black box + retention-caps-by-sink — and remove PostgreSQL, closing host :5432
_facet: observability-and-log-data-governance_

**Why:** Three proposals compose into one invariant that a 2–3 person team never has to re-audit: logs cannot contain free text (one emit_event(type, **fields) helper validating against frozen scalar/enum schemas, plus a CI lint rule — AST/ruff, not a bare grep), Agent Anone emits only a fixed verdict vocabulary and never serialises str(exc) or exc.args (it is definitionally the process that holds un-anonymised citizen/agent PII, and today it does logger.exception on a text-bearing exception and returns detail=f'erreur anonymisation: {exc}' which main.py folds into an outward-propagating reason string), and every sink is hard-capped at creation with a data_manifest.yaml entry. Follow the thread to its end: LangGraph's _t5_pending is already an in-memory dict, so if LiteLLM also runs stateless (no database_url, message logging off) then nothing uses PostgreSQL — remove the container and close the unauthenticated host :5432 entirely. That is a larger sovereignty win than any single logging fix and should be stated, not left implied. Corrections carried from the critiques: a Python logging.Filter cannot catch non-logging-module stderr (vLLM CUDA stack dumps, C-extension writes to fd 2) — handle those at the container log-driver level; 'reclassify the observability plane as non-personal' stays a DPO determination recorded in the DPIA, and the t5_ledger 'finance trail' still retains approver + request_id so it is limited personal data kept under an audit obligation, not non-personal; the /t5/pending preview (a LangGraph endpoint, not Anone) stays display-only as the human approver's last check before an Article 46 transfer — moot while v1 has no T5, but never logged or persisted.

**Sketch:** api/logging.py: emit_event + a stdlib filter collapsing stray records to {event: unstructured_log_suppressed, logger, level}; ruff/AST lint rule in CI; retrofit ~15 call sites (start with cascade_router.py str(e)[:60] and anone_api.py). Anone: uvicorn --no-access-log, top-level handler formatting type(exc).__name__ only, strip {exc}/str(e) from anone_api.py:97 and :129, bind Anone to the internal compose network and drop the host :8080 publish (the /deanonymize re-identification oracle must be unreachable from the host). Compose/daemon.json: Docker log-driver local with max-size/max-file AND a ~7–14 day time cap for LangGraph and Anone, Prometheus --storage.tsdb.retention.time/.size, Grafana annotations off, FastAPI access logs off fleet-wide, LiteLLM no database_url, remove the postgres service, unpublish :5432. data_manifest.yaml: one entry per sink (class E except the ledger). Review-checklist gate: every new compose service must ship logging limits + a manifest entry. Half a day of DPO time to co-sign the DPIA reclassification paragraph. Work: ~1–1.5 weeks.

### 5. Breach-readiness as four composed artefacts: content-free hash-chained scoping ledger + breach_playbook.yaml + ~6 fail-loud tripwires on one out-of-band channel + a sovereign-kill script
_facet: security-incident-detection-and-breach-notification_

**Why:** Today there is zero detection, zero containment reflex, and every hypothetical incident is therefore maximal ('assume all 5500 agents plus every citizen ever mentioned are exposed, notify everyone'), which is not a credible CNIL posture. The four proposals compose. (a) The forensic scoping ledger — implemented as the lint-enforced content-free schema plus a prev-hash field of the ALREADY-shipped LangGraph request log, not a new store — turns a maximal incident into '340 queries, 12 agents, 14:02–15:30, none Article-9, no T5' and directly populates the Art. 33(5) internal register; it is employee monitoring, so it needs a hard 12-month cap, a registre des traitements entry, a two-person rule to query by identity, and comite technique paritaire / DP sign-off, and the identity salt becomes a secrets_runbook.md rotation item. (b) breach_playbook.yaml pre-adjudicates the CNIL 72h decision as code, one entry per data store — moving the DPO/DGRH/DAF effort from a panic inside the window to a one-time drafting exercise (this attacks the dominant risk); the fail-safe is SPLIT — auto-default applies ONLY to the cheap, phaseable, reversible Art. 33 initial filing, while an unreachable primary DPO routes to a NAMED ALTERNATE decider before any expensive, irreversible Art. 34 data-subject notification; and it pre-agrees (DPO+DG signature) that citizen-side exposure is handled by a service-public.pf / press notice because content-free logging makes individual citizen notification infeasible by design. (c) ~6 fail-loud tripwires evaluated every minute on ONE out-of-band channel — but egress filtering via a single outbound forward proxy + a ~5-entry allowlist with a documented bed-in, NOT host iptables default-deny on a box where Docker rewrites the rules; the port tripwire is 'traffic on the host public interface', not 'any connection' (LangGraph->Ollama and LiteLLM->vLLM use those ports every request); the T5 alert is an absolute ceiling primary with the relative test secondary. (d) sovereign-kill: one idempotent script composing existing primitives (egress-zero, stop containers, revoke the Anthropic key, freeze the off-box ledger FROM THE DR SIDE, page the rota, write an incident record) with secrets rotation as a PROMPTED follow-up not inlined, a confirmation phrase, a dry-run mode, and a runbook that states the 'blackout returns 5500 agents to public ChatGPT' tradeoff and mandates 'IA indisponible, n'utilisez pas ChatGPT' user comms. All four exercised in the quarterly game-day.

**Sketch:** Add prev-hash + a lint-enforced content-free schema (timestamp, requester identity hash, sensitivity tier, tiers touched, T5 y/n, canary IDs, Art-9 lexicon hit y/n) to the shipped request log; one verify-chain cron on the DR box, or if DR is deferred, document explicitly where the authoritative off-box copy and the dead-man evaluator run in v1. breach_playbook.yaml: one entry per data store (corbeille, ledger, legal/money JSONL core, canonical base), DPO+DG signatures on the fail-safe split and the standing citizen-notification method, skeleton as obligation-mapped prose not a copy of the current teleservice form. ~200-line cron tripwire evaluator + a tinyproxy/squid forward proxy with a documented 'add to egress allowlist' step. sovereign-kill.sh with confirmation phrase, dry-run, auto-page, off-box who/why record. Local/.pf SMS or Signal route for the 2–3 person rota (content-free either way, but keep alerting metadata in PF). Update on every data_manifest.yaml change; test every game-day. Work: ~2 weeks, much of it one-time playbook coordination.

### 6. JML as one idempotent daily reconciliation batch + Entra-as-sole-system-of-record + de-identify-derived-data-at-promotion + scoped secret_holders.yaml
_facet: joiner-mover-leaver-lifecycle_

**Why:** At 5500 agents there is a leaver almost every working day, so any interrupt-driven or webhook lifecycle design is either quietly ignored (rule rot) or it crushes the ops team. Four proposals compose into a bounded daily ritual. (a) One idempotent daily reconciliation cron — preferably fed by a DGRH roster CSV export so the box holds no tenant-wide Graph directory-read credential (Graph cannot scope User.Read.All to an OU, so a popped box leaks the whole government directory); if Graph is used, certificate auth in the SOPS/age file and the blast radius named in the DPIA. It diffs the roster against oids owning local data, classifies JOINER (lazy-provision) / MOVER / LEAVER-SOFT / LEAVER-HARD, emits a plain-text action list to the ops mailbox, auto-applies non-destructive actions, one-click-confirms hard-erase — with a roster-shrink circuit breaker (>5% smaller than last successful run -> abort) and a MOVER-count circuit breaker, and NEVER a straight-to-hard-erase path (requires persisted SOFT state for N days AND confirmation the oid is in /directory/deletedItems). The DR copy is passive with a >48h takeover check. (b) Hold almost no per-agent durable state: key strictly on the immutable Entra objectId (UPN/mail churn on marriage and role change), scope fiche/canonical visibility on Entra security-group membership — one group per direction, ~30 groups, well under the F3 200-group token-overage limit — NOT on a department token claim, which Entra does not emit; quota is a calendar-month-aligned Redis counter. (c) De-identify derived data at the moment of promotion, not at erasure: the editor accepting a signalement writes a fresh record with provenance = editor role-ID + date and drops the oid link, so the eval harness and canonical base are class E by construction and leave BOTH the erasure drill and the JML lifecycle entirely — the highest-leverage sub-item, and it also stops the regression suite silently rotting as staff churn or request erasure. Call it 'de-identified pending the PII pass and DPO-signed class assessment', not 'non-personal by construction'; erase_subject() still scans the 90-day class-R promotion queue. (d) secret_holders.yaml (or derived from the Entra host-access group) names the <=5 humans who actually hold SSH/.env/SOPS-age/Anthropic-key access, so the adopted round-04 48h rotation rule fires only for them — do NOT re-open the round-04 cadence (quarterly basket B, annual Entra secret, provider-schedule Anthropic).

**Sketch:** reconcile.py daily cron + the two circuit breakers + passive DR copy with a timestamp takeover check; DGRH CSV drop if obtainable, else certificate-auth Graph app in SOPS/age with a DPIA blast-radius paragraph. Create ~30 Entra security groups (one per direction); migrate any stored role/department scoping to a groups claim or a cached login-time Graph /me lookup. Align the Redis quota TTL to the calendar month. Promotion tooling: copy-and-sever, store editor provenance as a stable role/oid (not a display name) registered in data_manifest.yaml, run the deterministic PII pass on promotion, 90-day class-R promotion queue that erase_subject() iterates. Charte-acknowledgement log keyed on oid with employment-status-driven pruning (depends on the reconciliation batch). config/secret_holders.yaml + 'add to secret_holders' as a mandatory line in the access-grant checklist + a reconciliation P1 flag when a listed holder is a LEAVER/MOVER-out. Work: ~1.5–2 weeks. Note the department-string -> allowlist maintenance and the Graph/CSV credential belong in the consolidated ~0.5 FTE total.

## Contradictions (and resolutions)

- DEFER T5 (whole-system 'substitution product') vs the adopted cloud stack (cloud_authorization.yaml runtime, GLiNER-for-cloud + outbound re-scan, Article 9 lexicon gate, durable t5_ledger, T5 fail-closed tests) and vs launch_authorization.yaml carrying a cloud gate. Resolution: v1 ships NO T5 runtime; cloud_authorization.yaml stays as a fail-closed stub and the Article 46 / SCC / TIA / Anthropic-DPA legal work runs in parallel owned by the launch_dossier (rank 1) because it is months-long lead time on the critical path. The cloud RUNTIME machinery is built only if a pre-committed v2 gate opens after the pilot. The anonymisation and lexicon layers that ALSO protect local-tier logging and the safeguarding lane stay live now; only their cloud-specific tuning waits.
- 'NO free-form chat box' (whole-system verbes proposal) vs the pilot shipping a drafting tool and vs the adopted embedding-kNN intent classifier vs the fact that ChatGPT's stickiness IS the free-form box. Resolution: adopt the four verbes (Chercher / Rediger / Traduire / Resumer) with deterministic per-verb routing and RETIRE the embedding-kNN classifier and auto-cascade (both proposals agree on killing invisible routing), but add one constrained fifth lane 'Poser une question' routed only to local search + local generation, never cloud, labelled 'sans IA cloud', and measure its fall-through rate to decide which verbes to add next. Resumer and Traduire are hard-pinned to local tiers with a soft degrade-not-block size cap and a 'ne collez pas de dossier nominatif complet' warning.
- PILOT COHORT: 'stratified representative sample, not volunteers' (whole-system rescue) vs 'genuine voluntariness' legally required by the Art. 6(1)(a) consent basis (foundational two-stage split). Resolution: the consent basis legally forces volunteers, so accept a ~15–25 person volunteer cohort from DSI and adjacent services and accept the enthusiast selection bias; compensate with the fall-through metric, structured exit interviews, and a plan to widen to a representative cohort at the Stage B / v2 transition on the 6(1)(e) basis where consent is no longer the basis.
- SECRET ROTATION CADENCE: JML proposal 3's 'all secrets rotate quarterly regardless of departures' vs the round-04 adopted cadence (quarterly basket B, annual Entra secret using the two-concurrent-secrets window, provider-schedule for Anthropic). Resolution: keep the round-04 cadence as the floor — do NOT force the Entra secret (needs an oauth2-proxy reconfig/redeploy) or the Anthropic key onto a quarterly treadmill for a 2-person team with no security gain. Adopt only the new artefacts: secret_holders.yaml (or derive it from the Entra host-access group) and the daily-reconciliation P1 flag.
- BREACH FAIL-SAFE: 'default NOTIFY if the DPO is unreachable at 24h' (breach_playbook proposal) vs the cost/reversibility asymmetry between Art. 33 and Art. 34 and vs 'crying wolf erodes the trust the whole stack exists to rebuild'. Resolution: auto-default applies ONLY to the Art. 33 CNIL initial filing (cheap, phaseable under Art. 33(4), effectively reversible). An unreachable primary DPO routes to a NAMED ALTERNATE decider (deputy DPO / legal director / DG delegate) before any Art. 34 data-subject notification, public service-public.pf notice, or press.
- EGRESS CONTROL MECHANISM: the tripwire proposal's 'default-deny egress via iptables' and 'any TCP connection reaching :11434/:4000/:5432 is hostile' vs Docker Compose reality (Docker rewrites iptables via DOCKER-USER; LangGraph->Ollama and LiteLLM->vLLM use those ports on the bridge every request; the box legitimately pulls models/HF/apt/pip/images/NTP/DNS). Resolution: egress filtering via ONE outbound forward proxy (tinyproxy/squid) + a ~5-entry allowlist with a documented bed-in and 'add to allowlist' step; the port tripwire fires only on traffic arriving on the host public interface, not on the compose network.
- OBSERVABILITY RECLASSIFICATION: the logging proposals assert 'the observability plane is provably metadata-only, therefore non-personal' and 'the t5_ledger is a non-personal CNIL/finance trail'. Contradiction with legal reality: request_id + timestamp + tier + pii_entity_count per query is behavioural data about an identifiable agent when request_id is linkable, and the ledger retains approver (a named agent). Resolution: build the structural text-free invariant (that part is sound), but the reclassification is a DPO determination recorded in the DPIA, not a build-time fact; the ledger is limited personal data kept under a finance/audit legal obligation and erase_subject() exempting it is a documented DPO decision.
- DR BOX: rank 5 (breach-readiness) wants the forensic-ledger authoritative copy and the dead-man evaluator hosted on a second-island DR box, while rank 3 (weekly ops) defers the second-island DR box to v2. Resolution: if the DR box is deferred, v1 must still ship the ledger off-box to SOME independent location (the DR partner's box if it exists in any form, or a minimal cheap off-site target) and document explicitly where the dead-man evaluator runs — it must not run on the primary's own cron. This is an open question for the operator (fund the DR box for v1, or accept the gap with sign-off).

## Facets / concerns still missed after 5 rounds

- Initial content bootstrap: who authors and LEGALLY VALIDATES the first 30–50 canonical fiches before launch, against which authoritative sources, and by when. This is a large one-time project distinct from the ~0.3–0.5 FTE ongoing editorial owner, and nothing in the adopted set costs or schedules it. An empty or thin canonical base at launch means the tool answers almost everything with 'generee localement non verifiee' and adoption collapses.
- Helpdesk self-impact: the Parc et Assistance cell IS the DSI support desk. Launching an assistant to 5500 agents generates a ticket surge — how-to questions, 'the AI gave me a wrong answer', access problems, 'why is it so slow' — that lands on the same 2–3 people who operate it. No facet modelled the launch support load, a tiered support model, or the FAQ/self-service needed to blunt it.
- Model licensing, provenance and AI-transparency posture: no facet covered legal review of the Mistral 7B / Llama 3.3 / Qwen 3 / Mistral Small licences and training-data provenance for a government deployment (redistribution terms, acceptable-use clauses, copyright exposure), nor whether la Polynesie francaise wants to voluntarily mirror EU AI Act GPAI / transparency obligations given its RGPD-alignment stance.
- Physical and environmental resilience of the single box: where it physically sits (which island, which building), UPS / cooling / physical access control, RTX 3090 procurement lead time and spares/warranty from Tahiti, and the runbook for replacing a dead GPU or PSU. The DR discussion is all logical; a fried 3090 with a 6-week replacement lead time is an unmodelled multi-week outage.
- Formal RGAA accessibility audit and the published declaration d'accessibilite — a legal obligation for PF public online services. The design claims 'RGAA-by-architecture' via a zero-JS client but no audit, no declaration, and no remediation budget is scheduled.
- Insider misuse / query-level purpose limitation: an authenticated agent using the assistant to look up or draft about a citizen they have no legitimate business reason to access. The system authenticates the agent but has no notion of the lawful purpose of a given query; the safeguarding and PII layers do not address curiosity-driven or malicious internal lookups.
- Anthropic contractual layer specifically: is there a signed DPA with written zero-retention / no-training commitments for the API tier, separate from the SCC + TIA? This is a v2 blocker with long lead time and should be started now even though T5 is deferred.
- Software supply-chain and maintenance load: version currency and CVE watch for LangGraph, LiteLLM, vLLM, oauth2-proxy, Ollama and the base images, plus abandonware risk, on a 2–3 person team with no staging environment. Patching a security bug with no staging and no eval harness is itself a risk the design has not addressed.
