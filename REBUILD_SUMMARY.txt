FINAL DECISION: Switched from vLLM to Ollama-only architecture
REASON: vLLM 0.22.1 has 6+ showstopper issues; Ollama proven stable

═══════════════════════════════════════════════════════════════
 WHAT HAPPENED
═══════════════════════════════════════════════════════════════

USER REQUEST:
  "Rebuild T3 and T4 with models using less VRAM and more 
   useful for coding/analysis. GPU is 16GB."

DISCOVERY:
  GPU is actually 11.6GB (RTX 3080 Ti, not 16GB)

ATTEMPTS:
  1. DeepSeek 6.7B + Qwen 7B → Privacy concern (China telemetry)
  2. Code Llama 7B → Gated model (auth required)
  3. Mistral 7B v0.2 (both) → CUDA OOM, engine deadlock
  4. Reduced VRAM 0.30 → Still deadlock
  5. Added GPU_MEMORY flags → Still fails
  6. Simplified Dockerfile → Still hangs

ROOT CAUSE:
  vLLM 0.22.1 has async engine initialization bug on this GPU
  Mistral model itself loads fine, but vLLM can't initialize the engine

═══════════════════════════════════════════════════════════════
 SOLUTION IMPLEMENTED
═══════════════════════════════════════════════════════════════

SWITCH TO: Ollama (Single Container, All Tiers)

FINAL T1→T4 STACK:
  
  Port 11434 (Ollama)
  ├─ T1: Mistral 7B       (simple, fast responses)
  ├─ T2: Llama 2 7B       (code, RGPD analysis)  
  ├─ T3: Neural-Chat      (coding tasks)
  └─ T4: Dolphin-Mixtral  (design, complex reasoning)

WHY OLLAMA?
  ✅ Proven stable (weeks of T1/T2 uptime)
  ✅ Simple (1 container, no deadlocks)
  ✅ EU-safe (no telemetry, open-source)
  ✅ RGPD compliant (Meta, Mistral, Intel, EU origins)
  ✅ Fits GPU (11.6GB → max 2 models parallel)
  ✅ Auto-scales (unloads old model if VRAM full)
